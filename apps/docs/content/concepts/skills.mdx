# Skills

## Skill

A **Skill** is a named capability you attach to an **Agent** — a description plus
a **Body** of instructions for doing something well. Rather than stuffing every
possible instruction into the Agent's **Instructions**, you give the Agent Skills
it can reach for when the moment calls for it.

The Agent only sees each Skill's _name and description_ up front. When it decides
a Skill is relevant, it requests that Skill's full instructions on demand. Only
the names and descriptions reach the [system prompt](/concepts/system-prompt), so
the prompt stays short until a Skill is needed.

**Why you'd use one:** to teach an Agent how to handle specific situations
without bloating its Instructions. A "Write a release note" Skill, a "Triage a bug
report" Skill, a "Format data as a table" Skill — each stays tucked away until the
Agent recognises it should use it.

## Invoking a Skill yourself

You don't have to wait for the Agent to pick a Skill. Type `/` at the start of a
message and choose one of the Agent's Skills, and its Body is loaded before the
Agent answers. A Skill marked **User-invocable only** is left out of the Agent's
catalogue entirely, so the model never reaches for it on its own — only a person
invokes it. See [Invoking a Skill by
name](/building-with-platypus/skills#invoking-a-skill-by-name).

## Where Skills live

A Skill lives at **Workspace scope** (private to one Workspace) or can be shared
at **Organization scope** as a [Shared resource](/concepts/sharing), so the same
know-how is reused across many Workspaces.

See [Building with Platypus → Skills](/building-with-platypus/skills) for how to
author one.
