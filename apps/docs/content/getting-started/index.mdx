# Getting Started

Platypus is a self-hosted platform for always-on AI agents — agents that reason,
use tools, and connect to your data through the Model Context Protocol. This
guide takes you from nothing to your first streamed reply.

The fastest path is the Docker quick start below, then a five-step loop:
**create a Workspace → configure a Provider → create an Agent → start a Chat →
send a message**.

## Before you start

- **Docker Engine with the Compose v2 plugin.** Every command here is
  `docker compose` (a space, not a hyphen). If `docker compose version` prints
  nothing, you have the old standalone `docker-compose` binary and the overlay
  files below won't merge the way this guide describes.
- **Ports `3000` and `4000` free on the host.** The frontend publishes `3000`
  and the backend `4000`. Postgres stays on the private network and publishes
  nothing.
- **`git`**, to clone the repository the compose file lives in.

## Quick start (Docker)

The quickest way to a running instance is Docker Compose.

<Steps>

### Clone and configure

```bash
git clone https://github.com/willdady/platypus.git
cd platypus
cp .env.example .env
```

Open `.env` and set, at minimum:

- **`BETTER_AUTH_SECRET`** — a secure random string (32+ characters). The app
  signs session tokens with this; treat it like a password.
- **`ADMIN_EMAIL`** / **`ADMIN_PASSWORD`** — the first admin account. **Required
  on first boot**: the backend exits rather than starting without them (see
  [First run](#first-run--the-default-admin) below).

The shipped `.env.example` fills in everything else for `localhost`, so a
laptop run needs no other edits. See the [Reference](/reference) for the full
list.

### Start the application

```bash
docker compose up -d
```

This brings up the backend, frontend, and a Postgres 17 database with pgvector.

### Sign in

Open [http://localhost:3000](http://localhost:3000) and sign in with the
`ADMIN_EMAIL` / `ADMIN_PASSWORD` you set in `.env`.

</Steps>

<Callout type="warning">
  If you left `.env.example`'s values in place, they are `admin@example.com` /
  `admin123`. **Change the password immediately after your first login**,
  especially on any network-reachable deployment.
</Callout>

Sign-in is **email and password**. There is no SSO, no OIDC and no SAML, and no
configuration that adds them — see
[Users & access](/self-hosting/users-and-access) if that is a go/no-go question
for you.

For a production-grade deployment — TLS, a reverse proxy, persistent storage,
and configuration hardening — see
[Running in production](/self-hosting/production).

## When the stack doesn't come up

The three failures that account for almost all of them, and what each looks
like:

| Symptom                                                   | Cause                                                                  | Fix                                                                                                                                        |
| --------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `docker compose ps` shows `backend` as **exited**         | A required variable is unset, or first-boot seeding failed             | `docker compose logs backend` — the last line names the variable or the seeding problem. Fix `.env` and `docker compose up -d` again.       |
| The backend sits in `starting` or goes **unhealthy**      | It cannot reach Postgres                                               | Check `docker compose logs database`, then that `DATABASE_URL` points at the `database` service rather than `localhost`.                    |
| Port already allocated on `3000` or `4000`                | Something else on the host holds the port                              | Stop the other process, or remap the host side in a `compose.override.yaml` and update `BACKEND_URL` / `ALLOWED_ORIGINS` to match.          |

You sign in successfully and are immediately signed out again? That is the URL
variables disagreeing, not a password problem — see
[Service URLs](/self-hosting/configuration#service-urls).

Deeper diagnosis, including recovering from a first boot that never completed,
is in
[Deploy with Docker Compose](/self-hosting/docker-compose#recovering-from-a-failed-first-boot).

## First run & the default admin

First boot against an empty database creates four things: a **Default
Organization**, an **admin user** from `ADMIN_EMAIL` / `ADMIN_PASSWORD`, that
user's membership of the Organization, and a **Default Workspace** named
_Default Workspace_ that the admin owns.

That admin account is the **Operator** — the platform super-admin who bypasses
in-app authorization. Sign in with it, and you are already inside a usable
Workspace; you don't have to create one. Add regular users for day-to-day work.

<Callout type="info">
  The seed runs when the database has **no Organizations**, and only then.
  Editing `ADMIN_EMAIL` / `ADMIN_PASSWORD` afterwards changes nothing — change
  the password from within the app. The full rule and the recovery path for a
  first boot that failed are in
  [what first boot creates](/self-hosting/docker-compose#what-first-boot-creates).
</Callout>

## Your first agent

Once you're signed in, here's the end-to-end loop to a working agent reply.

<Steps>

### Open your Workspace

After signing in you land on the **Default Organization**, which already
contains a **Default Workspace** you own — first boot created it. Click into it
to reach the Workspace dashboard, and skip straight to the next step.

Want a separate one anyway? Click **Add workspace**, give it a **Name**, leave
yourself as the **Owner**, and click **Save**.

> A **Workspace** is your scoped environment — it holds your Chats, Agents,
> Skills, MCP servers, and Providers. See [Concepts](/concepts) for how
> Organizations, Workspaces, and Agents fit together.

### Configure a Provider

A Workspace can't run an agent until it can reach a model. The dashboard shows
a **No providers configured** prompt — click **Add provider** (or go to
**Settings → Providers → Add provider**).

Fill in the form:

- **Provider Type** — your AI vendor. Exactly five: OpenAI, OpenRouter,
  Anthropic, Google, Bedrock. Running Ollama, vLLM or Azure OpenAI? Pick
  **OpenAI** and set **Base URL** — see
  [Supported vendors](/self-hosting/providers-and-auth#supported-vendors).
- **Name** — a label for this connection.
- **API Key** — your credential from that vendor.
- **Models** — a repeatable list, not a text box. Click **Add model** for each
  one and type its id into the **Model ID** field (e.g. `gpt-4o`,
  `claude-sonnet-4-6`). Leave **Alias** empty, **Context window** on **Not set**,
  and **Advanced** collapsed for now — every one of them is optional, and you can
  come back to them.

Click **Save**.

<Callout type="info">
  Don't have a key yet? [OpenRouter](https://openrouter.ai) gives you a single
  key that reaches many vendors and is a quick way to try Platypus.
</Callout>

### Create an Agent

From the dashboard's **Agents** section, click **Create agent**.

- **Name** — what to call the agent.
- **Model** — pick one of the models you enabled on your Provider (the dropdown
  groups models under each Provider).
- **Instructions** _(optional)_ — how the assistant should behave, e.g. _"You are
  a concise, helpful assistant."_ Platypus composes the system prompt around
  this; see [The system prompt](/concepts/system-prompt).

Click **Save**. An **Agent** pins a Provider, model, and Instructions (and,
later, Tools, Skills, and Sub-Agents) into a reusable preset.

### Start a Chat and send a message

Open a new Chat from the Workspace, then click the model selector and choose
your Agent under **Agents** (or pick a Provider + model directly).

Type a message in the input box and press **Enter**. The assistant's reply
streams back token by token — that's a **Chat turn** running end to end:
resolving your Agent's Provider and model, rendering its system prompt, and
streaming the model's response.

</Steps>

That's the full loop. 🎉
