# A2A endpoints

An **A2A endpoint** makes one Agent in your Workspace reachable from outside
Platypus over [A2A](https://a2a-protocol.org), the open protocol one agent uses
to talk to another. A client such as a messaging gateway or another agent
discovers the Agent through the endpoint's **Agent Card**, and authenticates
with a token you issue to it.

You'll find them under **Workspace settings → A2A endpoints**. Only the
Workspace Owner creates, edits and deletes endpoints and tokens. An Org Admin
opening your Workspace sees them read-only, and no Agent Tool can read or
change them. An Org Admin can
[revoke](/administering#see-and-revoke-endpoints) any endpoint or token in the
Organization, and you get a notification when they do.

## Before you start

Your Organization decides which Workspaces may have A2A endpoints, and it is
off until an Org Admin turns it on (see
[A2A endpoints](/administering#a2a-endpoints)). While it is off for your
Workspace, the screen says so and every endpoint answers **Not Found**. You can
still create endpoints and tokens in the meantime.

## Runs act as you

<Callout type="warning">
  Anyone holding a token can talk to the Agent, and every run acts as you, with
  every Tool the Agent has. A token is only as safe as the Agent's Tools are
  narrow. To expose less, make a narrower Agent and give the endpoint that one.
</Callout>

## Create an endpoint

<Steps>

### Open the form

Go to **Workspace settings → A2A endpoints** and click **Add endpoint**.

### Fill it in

- **Agent** — the Agent callers talk to. Any Agent in the Workspace, including
  an attached Shared Agent. You can't change it later.
- **Name** — what callers see as the agent's name, up to 100 characters. Leave
  it blank to use the Agent's name.
- **Description** — what callers see in place of the Agent's description, up to
  1000 characters. Leave it blank to use the Agent's description, then
  rewrite it for outsiders: the Agent's description is written for you and for
  other Agents.
- **Enabled** — when off, the endpoint answers every call with **Not Found**.
- **Include Memories** and **Extract Memories** — whether the endpoint's runs
  read your Memories and its Chats write to them. Both are off by default; see
  [Memories](#memories).

Click **Save**. The new endpoint's page opens.

### Add a token for each client

Under **Tokens**, name the token after the client it's for, up to 100
characters (for example `Hermes on Telegram`), pick how long it lasts — 30, 90,
180 or 365 days, 90 by default — and click **Add token**. Copy the token from
the dialog. It's shown once and Platypus keeps only a hash of it, so if you lose
it, regenerate it.

Give each client its own token. Deleting one stops only that client.

</Steps>

An Agent can have several endpoints. Give clients that should see a different
name or description their own endpoint, or retire one client's URL without
touching the others.

## Tokens

Each token on the endpoint's page shows its standing — **Active**, **Expiring
soon** (within 7 days) or **Expired** — when it expires, and when it was
**Last used** and **Last rejected**. **Last rejected** moves when a call with
the expired token is refused. Both times update at most once a minute.

- **Every token expires** after the lifetime you picked. A call with an expired
  token, like one with a missing or wrong token, gets `401 Unauthorized`.
- **You get a notification** 30 days and 7 days before a token expires (a
  30-day token only gets the 7-day one), and the first time a client uses it
  after it expires.
- **Regenerate** issues a new value for the token, with the same name and
  lifetime, and stops the old value at once. The new value is shown once. Use it
  when a token is about to expire, is lost, or may have leaked, then update the
  client.

<Callout type="warning">
  Rotating a token usually means updating the client's configuration, so act on
  the 30-day reminder, not the 7-day one.
</Callout>

## The Agent Card

Each endpoint has its own **Agent card URL**, shown on its page. The address is
generated for the endpoint, so it reveals nothing about the Agent or the
Workspace. Anyone with the URL can fetch the card, without a token:

```bash
curl https://platypus.example.com/a2a/<endpoint-id>/.well-known/agent-card.json
```

The card carries the endpoint's **Name** and **Description**, says the client
authenticates with an HTTP bearer token, names the address the client sends
requests to, and says the endpoint offers push notifications. It never carries the Agent's own description, Tool sets or
Skills.

An endpoint that is disabled or deleted, in a Workspace the Organization doesn't
allow, or whose Workspace Owner has left the Organization answers
**Not Found**, exactly like one that never existed.

A client that authenticates can also fetch the **extended Agent Card**
(`GetExtendedAgentCard`). It adds one skill, built from the same Name and
Description.

## Conversations

A client talks to the Agent by sending JSON-RPC requests to the endpoint's
address, with its token in an `Authorization: Bearer` header. A missing or
wrong token gets **401 Unauthorized**.

Each conversation is an ordinary Chat in your Chat list, labelled with the
token's name, so you can read what the client asked and what the Agent did. You
can continue the Chat yourself, and the client's next message follows your
turns.

- **`SendMessage` without a `contextId`** starts a new Chat with the endpoint's
  Agent. The answer's `contextId` is that Chat; send it with later messages to
  continue the conversation.
- **Each message is a Task.** `SendMessage` answers with the Task once the run
  has started. A client that sets `returnImmediately` gets it at once;
  otherwise the request waits up to **30 seconds** for the run to end, then
  answers with the Task as it stands. Runs can take far longer than that, so a
  client follows the Task with **`GetTask`** until it is `completed`, `failed`
  or `canceled`, or registers for a
  [push notification](#push-notifications) when it ends. The Agent's final
  reply is the Task's artifact.
- **A retry is safe.** The client's `messageId` becomes the message's id in the
  Chat, so sending the same `messageId` again answers with the Task it already
  started, never a second run.
- **One run at a time.** A message sent while the Chat still has a run going,
  including one you started in the Chat yourself, is refused with an error
  carrying the running Task's id. The client can follow that Task and send
  again once it ends.
- **Text and data parts.** Data parts reach the Agent as labelled JSON. A
  message with a file part is refused with an error rather than sent without
  it.

The Agent is told the conversation arrives over A2A from the client the token
is named after, and that the caller may not be you.

Streaming and cancelling a Task aren't offered yet: those methods answer with
an "unsupported operation" error.

## Push notifications

A client that doesn't want to hold a connection open or poll for hours can give
Platypus a URL to call when a Task ends. Register it with the message, in
`SendMessage`'s `taskPushNotificationConfig`, or afterwards on the Task with
`CreateTaskPushNotificationConfig`. `GetTaskPushNotificationConfig`,
`ListTaskPushNotificationConfigs` and `DeleteTaskPushNotificationConfig` read
and remove what a Task has.

- **Only the end is pushed.** When the Task becomes `completed`, `failed` or
  `canceled`, Platypus POSTs it to each URL registered on it, as
  `{ "task": { ... } }` with content type `application/a2a+json`. The Task is
  the one `GetTask` would answer, with the Agent's final reply as its artifact.
  Nothing is sent while it runs.
- **A Task that has already ended** when a URL is registered on it is pushed
  straight away, so a run that finishes before the client registers is not
  missed.
- **A run lost to a server restart** ends `failed` once Platypus notices it
  has gone quiet, and that is pushed like any other end.
- **Your credentials come back to you.** A request carries the
  `authentication` the client registered as an `Authorization` header (for
  example `Authorization: Bearer <credentials>`), and its `token`, if any, as
  `X-A2A-Notification-Token`. Check them on the receiving side to know the
  request came from this endpoint. An `authentication` without both a scheme
  and credentials is refused when it is registered.
- **Delivery works like a [Webhook](/building-with-platypus/webhooks#delivery-and-retries)'s**,
  with the same timeout, retries and network policy. A URL the policy blocks,
  such as a loopback or cloud-metadata address, is refused when it is
  registered.
- **Up to 5 URLs per Task.** Registering a URL that is already on the Task,
  without naming its `id`, replaces it rather than adding a second.

<Callout type="warning">
  The push carries the Agent's reply, so the receiving URL sees the
  conversation. Use an `https` URL you control, and check the credentials before
  trusting the body. A retry after a timeout can deliver the same Task twice, so
  handle a repeat of a Task id you've already seen. A push a server restart
  interrupts mid-delivery isn't sent again, so a client that must not miss an
  end should still poll `GetTask` now and then.
</Callout>

## Memories

Two switches on the endpoint decide how its conversations touch your Memories.
Both are **off** by default, because whoever holds a token may not be you.

- **Include Memories** adds your recent Memory summaries to the Agent's system
  prompt on the endpoint's runs. Off, the runs carry none.
- **Extract Memories** lets the endpoint's Chats feed your Memories. Off,
  Platypus never reads them for Memories — including any turns you add to them
  yourself in the Chat.

<Callout type="warning">
  A messaging gateway can put a stranger in front of the Agent: anyone in a
  group chat the client sits in. With **Include Memories** on, the Agent can
  repeat your personal context to them; with **Extract Memories** on, what they
  say lands in your Memories. Turn either on only for an endpoint whose tokens
  are held by you alone.
</Callout>

**Include Memories** applies from the endpoint's next run. Turning **Extract
Memories** on applies to the endpoint's existing Chats too, not only new ones.
A Chat started on an endpoint you later delete stays out of your Memories.

## Deleting

- **Delete** on the endpoint's page removes it. Its URL and every one of its
  tokens stop working at once.
- Deleting the Agent deletes its endpoints and their tokens.
- Detaching a Shared Agent from the Workspace deletes the Workspace's endpoints
  for it, and their tokens.
- An endpoint's Chats stay when the endpoint is deleted. Deleting a Chat ends
  its Tasks: `GetTask` answers that they don't exist.
